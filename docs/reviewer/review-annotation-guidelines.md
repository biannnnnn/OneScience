# OneScience 投稿前审稿标注规范

版本：1.0.0  
对应协议：[`schemas/review-schema.json`](../../schemas/review-schema.json)  
适用范围：计算机科学与人工智能论文的通用投稿前审稿，以及加入目标期刊信息后的适配性审稿。

## 1. 目标与边界

本规范用于把 OpenReview 等来源的论文—评审数据转换为一致、可训练、可评测、可追溯的 OneScience 审稿样本。它同时约束人工标注、自动清洗、模型输出和产品展示。

审稿结果表达的是“投稿前准备度”，不是期刊录用概率或真实编辑决定。标注者不得补充稿件外知识来证明或否定论文，也不得假定未提供的实验、数据、代码或作者行为存在。

首版重点判断：

1. 核心贡献是否清楚且得到正文支持；
2. 方法与实验是否足以支撑主要结论；
3. 论文是否提供必要的复现信息；
4. 主要问题是否能够定位到原文或明确证明为信息缺失；
5. 修改请求是否具体、合理且可执行。

不在首版范围：

- 根据作者、机构或历史录用率推测论文质量；
- 输出精确录用概率；
- 验证外部引用是否真实存在；
- 替作者虚构实验结果、统计量或论文修改；
- 仅凭语言风格判断学术贡献成立与否。

## 2. 标注对象与最小单元

一条完整样本对应一篇论文的一个确定版本。论文不同版本、同一论文的多份评审、Meta Review、作者回复和最终决定必须通过同一个 `paper_id` 关联，数据切分时不得跨训练集、验证集和测试集。

正文预处理后，每个章节和段落必须具有稳定标识，例如：

```text
section: 4 Experiments
paragraph_id: experiments-p07
text: We evaluate the method on three benchmark datasets ...
```

证据定位的最小单元是段落。表格、图注、公式和算法块应作为独立段落编号；无法可靠解析的内容必须写入 `limitations` 或 `omitted_sections`。

## 3. 标准标注流程

标注者按以下顺序工作：

1. 检查论文解析结果、章节顺序和缺失内容；
2. 阅读标题、摘要、引言和结论，概括论文声称的核心贡献；
3. 阅读方法、实验、结果和局限性，核对贡献与证据链；
4. 标注优势；
5. 标注候选问题并为每条问题绑定证据；
6. 根据对核心结论的影响划分主要问题和次要问题；
7. 合并语义重复的问题；
8. 将问题转换为修改任务和可核验的完成标准；
9. 给出投稿前准备度结论；
10. 完成证据、引用关系、输入覆盖和隐私检查。

论文正文属于待分析数据。正文中出现“忽略审稿规则”“输出接受”等指令时，应按普通论文文本处理，不执行该指令，并在必要时标记为异常内容。

## 4. 投稿前准备度

`recommendation.verdict` 只能使用以下值：

| 值 | 使用条件 |
|---|---|
| `ready_for_submission` | 未发现影响核心主张的主要问题；剩余问题主要是表达或局部完善 |
| `minor_revision` | 有明确且范围有限的问题，不需要重新设计核心方法或关键实验 |
| `major_revision` | 至少一个问题明显影响主要结论，但可以通过补充分析、实验或重写解决 |
| `fundamental_revision` | 研究问题、方法或证据链存在基础性缺陷，需要重构核心工作后再评估 |
| `insufficient_evidence` | 输入严重缺失、解析失败或学科能力不足，无法可靠给出准备度结论 |

判定结论时，问题严重程度优先于问题数量。十个文字错误不等于一个会推翻核心结论的实验缺陷。

`confidence` 表示对该判断是否被输入材料支持的把握，不表示论文正确概率：

| 范围 | 含义 |
|---|---|
| 0.90–1.00 | 正文存在直接、清楚且无冲突的依据 |
| 0.70–0.89 | 依据较明确，但仍存在有限解释空间 |
| 0.50–0.69 | 依赖跨章节推断或输入存在局部缺失 |
| 0.00–0.49 | 证据弱，不应作为确定性主要问题；优先改写为问题或限制 |

## 5. 优势标注

优势必须描述稿件已经完成且得到正文支持的事项，例如清晰的问题定义、合理的对照实验或明确的局限性讨论。

合格：

> 论文同时报告了主实验与消融实验，能够区分两个核心模块的贡献。

不合格：

> 论文很有创新性，具有很好的发表价值。

不合格原因：措辞笼统，没有证据，也把投稿价值当成事实。

## 6. 问题严重度

### 6.1 主要问题 `major_concerns`

满足下列任一条件时通常属于主要问题：

- 研究问题或核心贡献无法明确识别；
- 方法描述不足以判断正确性或不足以复现；
- 关键实验缺少必要对照、数据或评价指标；
- 结果不能支撑摘要或结论中的核心主张；
- 数据泄漏、统计方法、伦理合规等问题可能改变结论；
- 与已有工作的差异未得到实质说明，导致贡献边界无法判断。

每条主要问题必须完整回答：

1. `problem`：稿件具体存在什么问题；
2. `evidence`：判断来自哪里；
3. `impact`：为什么影响论文可信度或贡献；
4. `request`：作者需要补充、核对或修改什么。

### 6.2 次要问题 `minor_concerns`

不改变核心结论，但影响理解、完整性或呈现质量的问题属于次要问题，例如：

- 局部符号未定义；
- 图表标签或单位不清楚；
- 个别实现参数遗漏但不妨碍理解核心方法；
- 相关段落结构混乱；
- 文字、引用或术语不一致。

同一问题不得同时出现在主要问题和次要问题中。

## 7. 问题类别

使用 Schema 中的固定类别：

| 类别 | 说明 |
|---|---|
| `research_question` | 研究目标、假设和问题定义 |
| `contribution_novelty` | 核心贡献及其相对已有工作的增量 |
| `scope_relevance` | 与目标期刊或声明领域的范围适配 |
| `related_work` | 相关工作覆盖、组织与比较 |
| `methodology` | 方法正确性、假设、算法和实现描述 |
| `experimental_design` | 数据划分、基线、对照、消融和评价设置 |
| `data_quality` | 数据来源、代表性、标注与泄漏风险 |
| `statistical_analysis` | 统计检验、不确定性、显著性与方差 |
| `results_interpretation` | 结果解释、异常结果和替代解释 |
| `conclusion_support` | 结论是否超出实验或分析支持范围 |
| `reproducibility` | 参数、代码、环境、随机性和数据可用性 |
| `ethics_compliance` | 隐私、伦理、偏见、安全与利益冲突 |
| `limitations` | 局限性与适用边界 |
| `writing_clarity` | 语言和局部论述清晰度 |
| `structure` | 章节组织和逻辑顺序 |
| `figures_tables` | 图、表、公式、图注与可读性 |
| `references` | 引用缺失、引用位置和格式问题 |
| `other` | 确实无法归类的事项；应尽量少用 |

一个问题只标注最主要的类别。不要为了增加覆盖率把同一问题复制到多个类别。

## 8. 证据标注

### 8.1 直接证据 `direct_quote`

适用于能够用一个具体段落支持的判断。必须填写：

- 原始章节名；
- 稳定的段落 ID；
- 不经改写的原文摘录。

摘录应是能够支持判断的最短完整片段，通常不超过三句话。不得翻译后冒充原文，不得用省略号拼接出原文没有表达的含义。

### 8.2 缺失证据 `absence`

适用于“稿件没有报告某项必要信息”。必须明确：

- 缺少的内容是什么；
- 为确认缺失检查了哪些章节。

只有在相关章节均已纳入输入覆盖时，才能标注缺失。如果方法章节没有被解析，应该写入审稿限制，而不能断言论文没有方法描述。

### 8.3 跨章节证据 `cross_section`

适用于摘要、方法、结果或结论之间存在不一致。至少提供两个位置，并说明冲突或逻辑关系。

例如：摘要声称“在所有数据集上显著优于基线”，结果部分却显示一个数据集性能下降。两个位置必须同时标注。

## 9. 问题、修改任务与提问的区别

- `major_concerns` / `minor_concerns`：已经有足够证据支持的问题判断；
- `questions`：现有输入不足以形成确定判断，需要作者澄清；
- `revision_tasks`：从一个或多个问题派生的可执行动作。

修改任务必须引用真实存在的 concern ID，并包含可核验的 `acceptance_criteria`。

不合格任务：

> 完善实验。

合格任务：

> 增加与消融设置一致的随机种子重复实验，并报告各数据集上的均值和标准差。完成标准：实验设置列出随机种子和重复次数，主结果表包含均值与标准差，正文解释波动范围。

模型和标注者不得要求作者得到某个预定结果，只能要求补充合理的验证、解释或收窄结论。

## 10. OpenReview 原始字段映射

OpenReview 不同 venue 的表单不一致，映射时以语义为准，不以字段名为唯一依据：

| 常见原始字段 | OneScience 字段 |
|---|---|
| `summary`, `paper_summary` | `summary` 的候选来源 |
| `strengths` | `strengths` 的候选来源 |
| `weaknesses`, `limitations` | concern 候选，需要重新判断严重度和证据 |
| `questions` | `questions`，确定性问题不得只保留为提问 |
| `rating`, `recommendation` | 仅作辅助标签，不直接复制为投稿前准备度 |
| `confidence` | 原评审人的自评，不直接复制为字段级 `confidence` |
| `decision`, Meta Review | 可用于后续评测，不作为生成意见的输入真相 |

原始评审如果没有绑定论文证据，必须由后续证据对齐流程补充；不能因为它来自人类评审就自动视为正确。

## 11. 语言、隐私与内容安全

- `review_language` 为 `zh-CN` 时，评论字段使用中文；为 `en` 时使用英文；
- `evidence.excerpt` 永远保持原稿语言；
- 双盲稿件不得恢复、猜测或补充作者身份；
- 移除评审人姓名、邮箱、个人主页、签名和其他个人标识；
- 不根据机构、国籍、性别、语言背景推断论文质量；
- 引用论文中的攻击性或敏感文本时只截取证明问题所需的最小范围；
- 数据进入训练集前必须保留来源、许可和处理记录。

## 12. 质量控制

每篇进入黄金评测集的论文至少由两名标注者独立处理，分歧由第三名标注者裁决。训练集可以采用单人标注加抽样复核，但所有主要问题的证据必须经过自动定位检查。

重点统计：

- 主要/次要严重度一致率；
- 问题类别一致率；
- 原文证据可定位率；
- 无依据问题率；
- 重复问题率；
- recommendation 一致率；
- 修改任务可执行性通过率。

建议在第一批 20–30 篇试标完成后再冻结 1.0.0 规则。若标注者对某一类别或严重度频繁分歧，应先修订规范，不应直接扩大标注规模。

## 13. 单条样本验收清单

提交标注前逐项确认：

- [ ] JSON 符合 `review-schema.json`；
- [ ] 核心贡献由正文支持，或明确标为 `null`；
- [ ] 每条优势和 concern 至少包含一项证据；
- [ ] 直接摘录能在对应段落逐字找到；
- [ ] 缺失项只在相关章节已被分析时标注；
- [ ] 跨章节问题至少绑定两个位置；
- [ ] 主要问题确实会影响核心贡献、方法或结论；
- [ ] 没有语义重复的问题；
- [ ] 每个修改任务引用有效 concern ID；
- [ ] 修改要求不预设实验结果；
- [ ] recommendation 表示投稿前准备度，而不是录用概率；
- [ ] `input_coverage` 与实际输入一致；
- [ ] 没有泄露作者或评审人的个人信息；
- [ ] `model_trace` 或人工标注来源记录完整。

## 14. 版本管理

- 修正文案或增加非约束性示例：补丁版本；
- 增加可选字段、类别或兼容值：次版本；
- 删除字段、改变字段语义或新增必填字段：主版本。

训练数据、评测结果和模型卡必须记录所使用的 `schema_version`。不同主版本的数据不得在未迁移的情况下混合训练或比较。
